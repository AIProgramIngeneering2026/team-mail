# ADR-0001. Защита от повторного запроса через Idempotency-Key

Дата: 2026-11-14. Статус: принято.

## Контекст и ограничения
Клиент может повторить запрос из-за сбоя сети. Дубль уведомления недопустим.

## Решение
Клиент передаёт заголовок Idempotency-Key. Если Job с таким ключом уже есть,
возвращаем его с кодом 200, новый не создаём.

## Альтернативы
- Не защищаться: проще, но дубли писем.
- Сравнивать получателя и текст за последнюю минуту: ложные срабатывания.

## Цена решения
Нужно хранить ключи, клиент обязан их генерировать.

## Условия пересмотра
Если появятся клиенты, которые не могут передавать ключ.
