# Проверка колодой

| Карта | Ответ контракта |
|---|---|
| К1 Двойной клик | Создаётся один Job. Второй запрос с тем же Idempotency-Key получает 200 с прежним id: openapi.yaml, POST /jobs; ADR-0001 |
| К2 Ответ потерялся | Клиент повторяет запрос с тем же Idempotency-Key и получает 200 с id уже созданного Job, дубля нет. Тот же ключ с другим телом даёт 422 `idempotency_conflict`: openapi.yaml, POST /jobs; ADR-0001 |
| К3 Неизвестная операция | Ответ 404, тело в формате Error с кодом `not_found`, Job не создаётся. Неизвестный канал даёт 400 `validation_error` с полем `channel`: openapi.yaml, схема Error |
| К4 Кривые параметры | Ответ 400, тело Error: код `validation_error`, в поле `field` имя неверного поля (recipient, channel, text). Адрес и длину проверяет Tool в validate до создания Job, поэтому Job не создаётся: openapi.yaml, POST /jobs; tool-contract.md, validate |
| К5 Воскресение | Завершённый Job (delivered, failed, cancelled) не оживает: любой переход из него даёт 409 `invalid_transition`. Повторный запрос с тем же ключом возвращает прежний Job. Новая отправка это новый POST с новым ключом и новым id, прежний результат не меняется: architecture.md, диаграмма состояний; ADR-0001 |
| К6 Отмена | Поддерживается в accepted и sending: POST /jobs/{id}/cancel, ответ 200, дальнейшие попытки прекращаются. Из финальных состояний ответ 409. Уже ушедшее сообщение отозвать нельзя: openapi.yaml, cancel; ADR-0002, раздел «Отмена и гонка с доставкой» |
| К7 Огромный вход | Текст длиннее 4096 символов: 400 `validation_error`. Тело больше лимита: 413 `payload_too_large`. Поток запросов выше лимита: 429 `too_many_requests` с заголовком Retry-After. Клиент видит код и сообщение в формате Error: openapi.yaml, POST /jobs |
| К8 Чужой или несуществующий id | Один и тот же ответ 404 `not_found` для обоих случаев, поэтому чужие данные не раскрываются. Аутентификации нет сознательно: ADR-0003 |
| К9 Перезапуск сервера | После старта Job в sending старше 60 секунд переводятся в failed с причиной `interrupted`, повторной отправки нет. Исправляет сам сервис при старте: ADR-0002, раздел «Восстановление после перезапуска» |
| К10 Внешний сервис | Адаптер вызывает сервис с timeout 10 секунд и N повторами. Молчание или мусор в ответе: Job становится failed с причиной `timeout` или `bad_provider_response`. Клиент видит статус и причину в GET /jobs/{id}. Переименованное поле ловит проверка схемы ответа в адаптере и контрактный тест с fake: architecture.md, адаптер; tool-contract.md, ошибки Tool |
| Джокер | Сервис упал после того, как канал принял сообщение, но до записи статуса delivered. Job остаётся в sending и после перезапуска получает failed `interrupted`, хотя письмо ушло. Это сознательно принятая цена: лучше сообщить «не подтверждено», чем отправить дубль. Клиент сам решает, повторять ли: ADR-0002 |
